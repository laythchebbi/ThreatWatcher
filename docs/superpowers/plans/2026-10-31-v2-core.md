# Threat Watcher v2 — Plan 1 of 3: Core (app, auth, data model, watch cycle)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Express process in `app/` where a person signs up, adds a protected domain, and within one watch cycle sees its registered lookalikes as sightings and a timeline of events, with the watch re-running every six hours on its own.

**Architecture:** One Express 4 + EJS server over MongoDB (mongoose). Sign-in is built in: scrypt password hashes, a sealed iron-session cookie carrying `{ userId, sv }`. The watch is a set of pure functions (permute, DNS, diff) orchestrated per domain by `runCycle` and driven by an in-process scheduler that claims domains atomically. Permutations come from `dnstwist` running inside the existing Python worker, plus locally generated combosquats.

**Tech Stack:** Node 20, Express 4.22, EJS 3, express-ejs-layouts, mongoose 8, iron-session 8, zod 4, pino 9, helmet 8, compression, string-similarity, `node:crypto` scrypt, `node:test`, `mongodb-memory-server` (dev), Python 3.9 worker with `dnstwist`.

**Spec:** `docs/superpowers/specs/2026-10-30-threat-watcher-v2-design.md` (sections 7.1–7.4, 7.6, 7.9, step 1–3 of section 9). Plans 2 and 3 cover 7.4 steps 2, 3b, 4, 5a, 5b and 7.5, 7.7, 7.10.

## Global Constraints

- Plain CommonJS `.js`, `checkJs` via `tsconfig`, no TypeScript source, no build step, no front-end framework.
- Prettier (LF, 100 cols, double quotes), eslint flat config at the repo root; `.ejs` never goes through prettier.
- `node --test --test-reporter=spec` from `app/`; tests set placeholder env vars at the top so `config` loads.
- All gates green after every task: `npm run lint`, `npm run typecheck`, `npm test`, `npm audit` at 0 vulnerabilities (pin exact versions, no `^`).
- `backend/` and `frontend/` stay untouched and runnable until Plan 3 deletes them. `app/` is a third workspace.
- Port 3000 by default; local sanity boots use `PORT=3100` because another project holds 3000 on the owner's Mac.
- Password hashing: scrypt, 16-byte salt, N=2^14, r=8, p=1, `maxmem` passed explicitly, stored `scrypt$N$r$p$<salt b64>$<hash b64>`.
- Session cookie: 30 days, `httpOnly`, `sameSite=lax`, `secure` when `NODE_ENV=production`, re-sealed when older than 1 day, rejected when `sv !== user.sessionVersion`.
- Rate limits: login 10 per 15 min per email and per IP; `/signup` and `/forgot` 5 per hour per IP.
- Watch defaults: `WATCH_INTERVAL_HOURS=6` with ±15 min jitter, `WATCH_CONCURRENCY=3`, claim expiry 20 min, DNS 50 in flight, `MAX_DOMAINS_PER_ACCOUNT=5`.
- Severity ladder: `new_lookalike` low; `dns_live` medium; `mx_live` medium; `infra_changed` medium; `gone` low; punycode or substring bumps one level; MX present bumps every later event one level. (`cert_*`, `page_*`, `leak_*`, `posture_weak` are Plan 2.)
- Every watch step takes plain objects and injected dependencies (resolver, worker, fetch, clock) so tests use fixtures, never the network.

## Review Focus

1. A sign-up email with uppercase letters or surrounding spaces must map to the same account as the lowercase one; test in Task 4 (`signup normalises email`).
2. A domain added as `ACME-Corp.com` or with a trailing dot must be stored lowercase without the dot and rejected if it is not a registrable name; test in Task 5 (`add domain normalises and validates`).
3. A session cookie minted before a password reset must be rejected afterwards, not just on the next login; test in Task 3 (`readSession rejects stale sessionVersion`).
4. The dnstwist worker can return the protected domain itself or duplicates; the candidate list must never contain the protected domain and must be unique; test in Task 6 (`permutations drops self and duplicates`).
5. A sighting that stops resolving for exactly one cycle must not raise `gone`; two cycles must; and a return must raise `dns_live` only if the A set changed; test in Task 8 (`gone needs two misses`, `return re-fires dns_live only on changed A set`).

### Task 8: Severity ladder and the pure diff

**Files:**

- Create: `app/src/services/watch/severity.js`, `app/src/services/watch/diff.js`, `app/tests/diff.test.js`

**Interfaces:**

- Consumes: `similarity.scoreDomains`, `isPunycode`, `isSubstringMatch` (Task 6).
- Produces: `severity.js`: `LEVELS = ["low","medium","high","critical"]`, `bump(level, steps = 1) → level` (clamped), `BASE = { new_lookalike: "low", dns_live: "medium", mx_live: "medium", infra_changed: "medium", gone: "low" }`, `eventSeverity(kind, sighting) → level` = `BASE[kind]` bumped once if `sighting.punycode || sighting.substring`, bumped once more if `sighting.dns.mx.length > 0` and kind is not `mx_live`.
- Produces: `diff.js`: `diffDomain({ domain, previous: Sighting[], observed: Map<name, dns>, candidates: string[], lists, now, baseline: boolean }) → { upserts: SightingFields[], events: EventFields[] }` where a `SightingFields` is the full document minus ids and an `EventFields` is `{ lookalike, kind, severity, payload }`. Rules (spec 7.3):

  - candidates are scored with `scoreDomains(domain.name, candidates, 0.7)`; names that score below 0.7 and do not resolve are dropped; names that resolve are kept regardless of score (a resolving combosquat counts).
  - new name → upsert with `firstSeenAt = now`, `baseline`, event `new_lookalike`; if it resolves also `dns_live` (and `mx_live` if MX) in the same cycle.
  - previously resolving, now missing: `dnsMisses += 1`; at `dnsMisses === 2` → `inactive = true`, event `gone`; at 1 → no event.
  - previously inactive, now resolving: `inactive = false`, `dnsMisses = 0`, event `dns_live` only if the A set differs from the stored one.
  - resolving both times with changed A, NS or MX set → `infra_changed` with payload `{ before, after }` naming the changed keys; a newly present MX → `mx_live`.
  - `infra` recomputed with `classifyInfra`; a sighting with `parked: true` and no resolving-page signal gets its `dns_live` and `infra_changed` severities set to `low` (watch, not alert).
  - `state === "ignored"` → upsert `lastSeenAt` only, no events. `state === "dismissed"` → events are produced only if their severity is above `dismissedAtSeverity`, and then the upsert sets `state = "open"`.
  - `baseline === true` cycle → every event gets `payload.baseline = true` (Plan 3 skips alerting on these); sightings get `baseline: true`.
  - `severity` on the upsert = highest severity of any open event ever raised for it (keep `max(prev.severity, new events)`).
